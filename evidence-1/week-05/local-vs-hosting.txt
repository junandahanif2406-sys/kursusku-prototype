Refleksi singkat:
​1. Apa risiko jika prototype ini langsung diunggah ke hosting publik tanpa HTTPS?
Data yang dikirimkan oleh pengunjung, seperti isian form pendaftaran kursus, akan dikirim dalam bentuk teks biasa (tidak terenkripsi). Ini sangat berisiko disadap oleh peretas di jaringan. Selain itu, browser akan memberikan peringatan "Not Secure" yang menurunkan kepercayaan pengunjung terhadap web KursusKu.
​2. Bagian mana dari kode Anda (jika ada) yang masih menulis path lokal atau informasi yang tidak boleh dibagikan ke publik?
Saya harus memastikan pemanggilan file seperti CSS dan gambar menggunakan path relatif (contoh: assets/css/style.css atau assets/images/hero-kursus.jpg), bukan path absolut yang mengarah langsung ke drive lokal komputer saya. Selain itu, jika nanti ada konfigurasi koneksi ke database MySQL, kredensial lokal Laragon (seperti username root tanpa password) tidak boleh ikut terunggah ke repositori publik di GitHub.
​3. Apa perbedaan utama cara menangani error di local vs production menurut Anda?
Di lingkungan lokal, menampilkan detail pesan error PHP sangat penting agar saya bisa mengetahui letak kesalahan kode dan memperbaikinya dengan cepat. Namun, di production (hosting), detail error tersebut wajib disembunyikan dan diganti dengan halaman pemberitahuan yang lebih ramah pengguna. Menampilkan error detail di production sama saja dengan membeberkan struktur direktori dan potensi celah
